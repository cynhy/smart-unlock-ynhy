# Smart Unlock 使用说明书（6.4.6）

适用版本：`com.watchunlock.app` **6.4.6**（versionCode 646）
适用系统：Android 8.0 及以上（arm64-v8a）；Android 17 / 澎湃 4 已适配
文档类型：用户操作手册
技术细节：见 `E:\guocheng\交接文档-6.4.6-2026-11-24.md`

> 一句话：让手机在指定蓝牙设备（手表 / 手环 / 耳机 / 车机）在线时，亮屏自动输入锁屏 PIN。
>
> 开始前请确认：锁屏方式是 **4–16 位纯数字 PIN**，并且你接受「应用会以 shell 权限执行解锁脚本」这一前提。

---

## 1. 能做什么

- 绑定一个或多个蓝牙设备；任一在线或全部在线时触发解锁。
- 可选用 WiFi 作为解锁条件：WiFi 独立解锁，或「蓝牙 + WiFi」同时满足。
- 亮屏后自动执行 `wm dismiss-keyguard` + `input text <PIN>`，直接进入桌面。
- 支持「特殊锁屏返回」：解锁后打开指定应用，或向右滑动，解决音乐锁屏停留在音乐页的问题。
- 支持暂停、日志、一键清理、内置 ADB 控制台。
- 支持 Shizuku / Root / 内置无线调试三种授权方式；另有网页版 ADB 备用入口。

**不支持**：图案锁、混合密码、纯指纹 / 人脸解锁、多用户 / 工作资料。

## 3. 安装

### 3.1 正常安装

1. 拿到 `watch-unlock-6.4.6-signed.apk`。
2. 点击安装；如果提示「签名冲突」，说明旧包不是同一签名，需要先卸载旧版（应用内设置会丢失）。
3. 安装后先不要急着部署，按第 4 节完成授权。

> 未签名包不能直接安装，也不能上传到任何发布渠道。

### 3.2 小米 / 澎湃安装（adb install 被拦截时）

如果 `adb install` 报 `INSTALL_FAILED_USER_RESTRICTED` 或 `INSTALL_CANCELED_BY_USER`：

```powershell
adb push watch-unlock-6.4.6-signed.apk /sdcard/Download/watch-unlock-6.4.6.apk
adb shell am start -a android.intent.action.VIEW `
  -d file:///sdcard/Download/watch-unlock-6.4.6.apk `
  -t application/vnd.android.package-archive
```

保持屏幕解锁；安装器可能先停在准备页，几秒后自动完成。

## 4. 授权

打开应用 → 设置 → **授权方式**。三种方式任选其一；**切换后必须重新「部署并启用」**。

### 4.1 Shizuku（推荐）

1. 安装并启动 Shizuku（可用无线调试或 root 启动）。
2. 本应用 → 设置 → 授权方式 → Shizuku → 「请求授权」。
3. 在 Shizuku 弹窗里允许。
4. 建议把 Shizuku 与本应用都加入电池优化白名单。

### 4.2 Root

1. 开发者选项 → Root access → 「Apps and ADB」。
2. 本应用 → 设置 → 授权方式 → Root。
3. 点「检测 Root 授权」，在 su 弹窗里允许；首次可能需要等 15–30 秒。
4. 回主页 → 「部署并启用」。

说明：6.3.7 起复用常驻 `su` shell，不再每次操作重新拉起；不需要 Magisk 模块。

### 4.3 内置无线调试（Android 11+）

1. 允许本应用发送通知。
2. 本应用 → 无线调试 → 「开发者选项」→ 打开「无线调试」。
3. 点「使用配对码配对设备」，**保持系统弹窗打开**。
4. 输入 6 位配对码，三选一：
   - **通知内联输入**：下拉通知，点「输入配对码」，在通知里输入；不要点通知正文。
   - **大按钮输入**：点通知里的「大按钮输入」，在独立页面输入后点一次「发送」。
   - **分屏手动配对**：本应用与设置页分屏，在「手动配对」里填端口与配对码。
5. 配对成功后自动连接；端口变化时用「连接测试」手动重连。

小米 / 澎湃注意：

- 通知里没有输入框 → 系统设置 → 通知管理 → 通知显示设置 → 切换为「原生样式」。
- 电池策略设为「无限制」，避免配对服务被清理。
- 重启后无线调试会自动关闭、端口变化，需要重新打开并配对。

> 6.4.0 之前（含 6.3.9）无线调试有已知 bug；6.4.6 已沿用修复。

### 4.4 网页版 ADB（备用）

设置 → 授权方式 → 第 4 项「网页版 ADB（USB，免回环端口）」→ 用 Chrome / Edge 打开 `https://czjam.github.io/gjgjxweb/`。

- 网页由晨钟酱（CzJam）维护，版本 6.3.9，GPL-3.0，是外部页面，本应用未打包、未修改。
- 主机不能是 iOS / Firefox；被调试端必须是安卓，并打开 USB 调试。
- 这个入口不会改变当前授权方式，只作为无线调试失效时的备用通道。

## 5. 首次配置

### 5.1 授予权限

首次打开会请求通知、附近设备权限，全部允许。Android 13+ 的通知权限也要允许，否则前台服务通知与配对通知会异常。

### 5.2 勾选蓝牙设备

1. 先让手表 / 耳机 / 手环与手机完成系统蓝牙配对。
2. 主页「蓝牙设备」→「重新扫描」。
3. 勾选目标设备；**新发现设备默认不启用**，不勾选不参与判定。
4. 需要「任一在线」保持默认；需要所有设备都在线，打开「多设备模式」。
5. 信号弱、隔墙容易误触发时，可设置 RSSI 下限。

### 5.3 可选：WiFi 条件

- **WiFi 解锁**：连着指定 WiFi 就能单独触发解锁。
- **WiFi 为必要条件**：蓝牙在线之外，还必须连着指定 WiFi。
- 只能添加**当前已连接**的 WiFi：先连上它，再点「添加当前 WiFi」。
- 开启「增强防护 → WiFi → 绑定 BSSID + 要求非开放网络」后，运行时会同时比对 BSSID；开放网络默认拒绝，可在同页允许。

### 5.4 输入锁屏 PIN

在主页输入与系统锁屏一致的 4–16 位数字 PIN。

- PIN 保存在应用私有设置中，部署时写入 `/data/local/tmp/watch-unlock/pin`（权限 600）。
- 不会写入 `/sdcard`，也不会出现在 `config.conf`。
- 如果 PIN 改了，应用内也要改，否则连续失败会进入冷却 / 停用。

### 5.5 部署并启用

回主页 → **「部署并启用」**。看到状态变为「运行中」即可。

然后锁屏、息屏、再点亮屏幕测试：蓝牙设备在线时应自动输入 PIN 并进入桌面。

### 5.6 Android 17 / 澎湃 4 用户

设置 → 解锁增强 → **「Android 17 适配」保持开启**（默认开启）。

- 开启：使用新的锁屏判定 + 亮屏低频轮询 + 键盘焦点等待。
- 关闭：不轮询、不等焦点，解锁更快，但本机实测会完全不解锁。
- 只有确认关闭后仍能正常解锁的机器，才建议关闭以减少解锁耗时。

## 6. 日常使用

### 6.1 改设置

6.3 起，改开关、设备、WiFi 或 PIN 会**自动写入配置并热重载**，一般不需要重新部署。

以下情况需要再点「部署并启用」：

- 第一次使用；
- 切换授权方式；
- 升级或重装 APK；
- 守护被停用（连续两个冷却周期失败）；
- 提示「设置已保存，但未写入守护」。

### 6.2 暂停 / 恢复

主页可「暂停 15 分钟 / 1 小时 / 4 小时」或输入自定义秒数；点「恢复」取消暂停。暂停期间守护仍在运行，只是不执行解锁。

### 6.3 看日志

设置 → 日志：

- 可自动刷新、复制、清空；
- 日志超过 1 MB 自动轮转为 `wu.log.old`；
- 反馈问题时附日志截图，并注明手机型号与系统版本。

常见 `skip` 原因：

| 日志 | 含义 |
| --- | --- |
| `skip: already unlocked` | 亮屏时本来就没锁屏 |
| `skip: not on keyguard` | 当前不在锁屏界面 |
| `skip: 解锁条件不满足` | 蓝牙 / WiFi 条件没满足 |
| `skip: sim locked` | SIM 卡处于 PIN 锁定，防呆拒绝注入 |
| `skip: another attempt running` | 另一个解锁进程正在执行 |
| `skip: recent injection` | 1.5 秒内已经注入过 |
| 冷却 / 暂停 | `wu.state` 里有冷却截止或暂停时间 |

### 6.4 一键清理残留

主页「一键清理残留」会：

- 停守护、杀残留进程；
- 停监控服务、无线调试配对服务与 mDNS 发现；
- 删除 `/data/local/tmp/wu.*` 与旧 `/sdcard/watch-unlock`；
- **保留**应用内设置、设备勾选与 WiFi 列表。

清理后解锁停止，需要重新「部署并启用」。

## 7. 设置项说明

### 7.1 特殊锁屏返回 / 解锁后打开应用

有些 ROM 在音乐锁屏输入 PIN 后会停在音乐页：

- 打开「特殊锁屏返回及解锁打开指定应用」；
- 点「选择应用」选一个应用（单选），解锁后自动打开；
- 或打开「向右滑动」，解锁后执行一次右滑；
- 两者同时开启时优先打开应用；包名解析失败时退回右滑（若开启）。

如果打开应用无效，给本应用授予「后台弹出界面 / 自启动」权限。

### 7.2 增强防护

主页右侧「增强防护」卡片是总开关，二级页面有：

| 开关 | 建议 |
| --- | --- |
| 蓝牙身份匹配（只认 MAC） | **本版停用，不可操作**；随机 MAC 会导致正常设备被判离线 |
| MAC 对不上时允许同名设备 | 随上一项停用 |
| WiFi 绑定 BSSID + 要求非开放网络 | 需要防同名假热点时开启；2.4G / 5G 需分别添加 |
| 允许开放网络也成立 | 默认关闭，按需开启 |
| 每次解锁前都现场查询设备状态 | 状态不准时再开；每次亮屏多花 0.2–0.35 秒，耗电略增 |

### 7.3 延长解锁（实验性，谨慎开启）

作用：设备在身边时临时清除锁屏密码，亮屏直接进桌面。

开启步骤：

1. 主页填写与系统一致的 PIN；
2. 高级 → 延长解锁；
3. 依次通过三级确认（5 秒 / 2 秒 / 2 秒），并校验系统 PIN。

恢复规则：

- 所有启用的蓝牙设备与 WiFi 条件都不再成立后，会立即、+0.5 秒、+1.5 秒各判定一次；
- **三次都离线**才写回原 PIN；
- 关闭开关、停止守护、一键清理会立即写回。

必须知道的风险：

- 密码清除期间，指纹 / 人脸会失效，恢复后要重新录入；
- 部分 ROM 不支持，可能直接失败（失败会回滚）；
- 守护被系统杀死、授权失效、重启后守护未运行等情况下，密码可能不会自动恢复；
- 不建议在主力机上长期开启。

异常处理：点「立即恢复锁屏密码」；仍不行就到系统设置里重新设置锁屏。

### 7.4 内置 ADB 控制台

无线调试页可直接执行一条 `adb shell` 命令，适合排查问题：

```sh
sh /data/local/tmp/watch-unlock/wu-daemon.sh --check
```

会打印设备命中数、在线状态、WiFi、RSSI、锁屏、暂停、冷却、延长解锁、A17 适配等。

## 8. 常见问题

| 问题 | 处理 |
| --- | --- |
| 亮屏完全没反应 | 看日志是否有 `skip`；确认守护状态「运行中」；确认至少勾选了一个设备；Android 17 确认「Android 17 适配」开启 |
| 提示设备不在线 | `--check` 看 `watch_hit` / `match_mac`；确认设备已配对、名称未被系统改过 |
| 解锁很慢 | 关闭「每次解锁前都现场查询」和 RSSI 下限；看日志 `timing:` 分段 |
| 解锁后停在音乐页 | 开启「特殊锁屏返回」并选择应用，或开启右滑 |
| 改设置没生效 | 看设置页提示；若提示未写入守护，点「部署并启用」 |
| 重启后失效 | 守护随重启消失；重新启动 Shizuku 并授权，或重新配对无线调试，然后部署 |
| 小米 / 澎湃后台被杀 | 电池策略「无限制」、允许自启动；通知样式「原生样式」 |
| 无线调试配对失败 | 确认 6.4.0+；保持配对弹窗打开；分屏 + 手动配对；点「重新搜索配对服务」 |
| 搜不到配对服务 / 找不到连接端口 | 6.4.0 起会自动重试并等待端口（最长 25 秒）；超时后手动填写端口，点「连接测试」 |
| Root 点了允许仍不可用 | 确认开发者选项 Root access 为「Apps and ADB」；root 管理器对「应用」放行；再点「检测 Root 授权」 |
| Root 解锁偶发无响应 | 抓 `wu.log` 里的 `su` / `timing` 行反馈；先切到 Shizuku 观察是否复现 |
| 网页版 ADB 打不开设备 | 换 Chrome / Edge；确认数据线支持数据传输；目标端开 USB 调试并允许 RSA；手机主机需 OTG；iOS / Firefox 不行 |
| 连续两个冷却周期失败后停用 | 多半是系统 PIN 变了；在应用里改成新 PIN，再重新部署 |
| 延长解锁后指纹失效 | 预期行为；恢复密码后重新录入指纹 / 人脸 |
| 延长解锁没有自动恢复 | 点「立即恢复锁屏密码」；不行就系统设置里重设锁屏 |
| 耗电变高 | 看设置里是否开启「每次解锁前都现场查询」；A17 轮询约 0.2–0.4 mA，属于固定底噪 |

## 9. 升级与卸载

### 9.1 升级

1. 用**同一签名**的新 APK 覆盖安装。
2. 打开应用，点一次「部署并启用」（守护脚本随 APK 更新，旧脚本不会自动替换）。
3. 检查设置是否保留，锁屏测试一次。

### 9.2 卸载 / 彻底清理

1. 先在应用里点「一键清理残留」。
2. 再卸载应用。
3. 如果之前开过延长解锁，清理前务必确认已「立即恢复锁屏密码」。

## 10. 安全与隐私

- PIN 会以明文保存在 shell 私有目录（权限 600），这是锁屏注入的必要代价。
- Shizuku / Root / 无线调试都会给应用 shell 能力，请只安装可信来源的 APK。
- 延长解锁会临时移除锁屏密码，设备丢失时风险很高。
- 应用不联网、不上传数据；无线调试的 mDNS 只在局域网内发现本机端口。
- 「网页版 ADB」是外部网页，首次加载需要联网；打开后由浏览器直连 USB 设备，数据不经过本应用。请从官方地址进入。
- 日志包含设备名、MAC、SSID，公开反馈前请先打码。

## 11. 6.4.6 与 6.4.3 的差异

| 项 | 6.4.3 | 6.4.6 |
| --- | --- | --- |
| Android 17 锁屏判定 | 只看 `mIsShowing`，A17 失效 | `KeyguardServiceDelegate showing=` 兜底 |
| 亮屏事件 | 依赖 logcat / 应用广播 | 增加 0.9 秒低频轮询兜底 |
| 密码键盘 | dismiss 后直接注入 | 等键盘焦点后再注入 |
| 设置项 | 无 | 「解锁增强 → Android 17 适配」（默认开） |
| 后台耗电 | 无轮询 | 约 0.2–0.4 mA（0.3–0.5% 单核） |
| 其他功能 | — | 与 6.4.3 一致 |

> 本机（小米澎湃 4 / Android 17）实测：开启适配约 580–620ms 解锁；关闭后 8 秒以上无触发，完全不解锁。其他机型可自行测试关闭后是否正常。
