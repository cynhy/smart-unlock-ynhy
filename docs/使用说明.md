# Smart Unlock 使用说明（6.3.9）

适用于包名 `com.watchunlock.app`、版本 `6.3.9` 的安装包。本文是面向使用者的操作手册；原理、配置字段和构建方式见 [详细说明](详细说明.md)。

> 一句话：**让手机在指定蓝牙设备（手表、耳机、手环）在线时，亮屏自动输入锁屏 PIN。**
>
> 开始前请确认：锁屏方式是 **4～16 位纯数字 PIN**，并且你接受「应用会以 shell 权限执行解锁脚本」这一前提。

> **版本提醒**：6.3.9 是 6.3.7 的定版，版本号 639，仍属于测试版；官方标注的稳定版只有 **1.1、3.3.3、6.3.6**。6.3.9 沿用 6.3.7 重写的内置无线调试（随包官方 ADB）、Root 稳定性修复与「网页版 ADB」备用通道；不想折腾请继续用 6.3.6。

## 1. 准备清单

| 项目 | 要求 |
| --- | --- |
| 手机系统 | Android 8.0 及以上 |
| 锁屏方式 | PIN（纯数字），不能是图案或混合密码 |
| 授权方式 | 三选一：Shizuku / Root / 内置无线调试（无线调试需 Android 11+） |
| 权限 | 通知、附近设备（Android 12+ 蓝牙）；无线调试还需网络权限 |
| 建议 | 电池策略设为「无限制」，允许自启动 / 后台弹出界面 |
| 蓝牙设备 | 已在系统设置里与手机配对 |
| 网页版 ADB（可选） | 另一台非 iOS 设备 + Chrome / Edge 等 Chromium 浏览器 + 数据线 / OTG |

## 2. 安装

1. 拿到 APK。正式包与测试包**签名不同，不能互相覆盖安装**；如果提示签名冲突，先卸载旧版（应用内设置会丢失）。
2. 如果拿到的是 `watch-unlock-6.3.9-unsigned.apk`，需要先用你自己的密钥签名，再安装：

```powershell
apksigner sign --ks <你的密钥库> --ks-pass pass:<口令> `
  --out watch-unlock-6.3.9-signed.apk watch-unlock-6.3.9-unsigned.apk
```

3. 安装后先不要急着部署，按下一节完成授权。6.3.9 的 versionCode 是 639，可覆盖 6.3.6（636）及更早的同一签名版本；已装 6.3.7（637）也可直接覆盖升级。
4. **未签名包不要直接安装**，也不要把未签名包上传到任何发布渠道。

## 3. 选择并完成授权

打开应用 → 设置 → **授权方式**。三种方式任选其一，切换后必须重新部署。

### 3.1 Shizuku（推荐，免 root）

1. 安装并启动 Shizuku（可用无线调试或 root 方式启动）；
2. 回到本应用 → 设置 → 授权方式 → Shizuku → 点「请求授权」；
3. 在 Shizuku 弹窗里允许本应用；
4. 建议把 Shizuku 和本应用都加入电池优化白名单。

### 3.2 Root（6.3.7 起重点修复稳定性）

1. 开发者选项 → Root access 设为「Apps and ADB」（不同 ROM 名称略有差异）；
2. 本应用 → 设置 → 授权方式 → Root；
3. 点「检测 Root 授权（会弹出 su 请求）」，在弹窗里选「允许」；
4. 回到主页 → 「部署并启用」。

说明：

- 6.3.7 起会复用一条常驻 `su` shell，不再每次操作都重新拉起 `su`，亮屏解锁和状态刷新更快；
- 首次检测会等 15 秒（部署时更久），给 root 管理器弹窗留出确认时间；
- 如果刚点「允许」仍提示不可用，等 20 秒或再点一次「检测 Root 授权」；
- 若始终失败，确认设备真的已 root，且 root 管理器允许「应用」请求（不只是「ADB」）。

无需 Magisk 模块。

### 3.3 内置无线调试（随包官方 ADB，免 root，Android 11+）

应用内置官方 AOSP adb 客户端（Termux android-tools 37.0.0p1 构建，Apache-2.0），以本应用自身的 uid 执行 `adb pair` / `adb connect` / `adb shell` / `adb push`。6.3.7 起已完全移除第三方 Kadb 内核，6.3.9 沿用同一实现。

> APK 里带了一个 adb 可执行文件和约 4.5MB 的依赖库；首次配对时会解压到应用私有目录，需要几秒，之后不再重复解压。

1. 先允许本应用发送通知（用通知方式输入配对码时需要）；
2. 本应用 → 无线调试 → 点「开发者选项」，系统会跳到开发者选项并尽量把「无线调试」滚到可见位置；
3. 点「无线调试」左侧进入子页面，打开开关；
4. 点「使用配对码配对设备」，**保持这个弹窗打开**；
5. 应用会自动发现配对端口。输入配对码二选一：
   - **通知**：下拉展开通知，点「输入配对码」，在通知里输入弹窗中的 6 位码；不要点通知正文；
   - **分屏**：本应用与设置页分屏显示，在「手动配对」里填配对端口和 6 位码，点「配对」；
   **无论哪种方式，都不要关闭系统配对弹窗**——离开弹窗后端口和配对码会立即失效；
6. 配对成功后自动连接本机 ADB；连接端口也可用页面下方的「连接测试」手动重连。

小米 / 澎湃用户注意：

- 通知里没有输入框 → 系统设置 → 通知管理 → 通知显示设置 → 切换为「原生样式」；
- 把本应用电池策略设为「无限制」，避免配对服务被后台清理；
- 重启手机后无线调试会自动关闭、端口变化，需要重新打开并再配对一次。

### 3.4 网页版 ADB（USB，免回环端口；6.3.7 新增备用通道）

**什么时候用**：谷歌可能进一步收紧「本机回环 ADB」（`127.0.0.1`）的配对与授权。如果你遇到无线调试无法配对、连接被拒，或者未来系统更新后回环 ADB 失效，可以用网页版 ADB：不经过手机自己的 adbd 回环端口，改由浏览器通过 **WebUSB** 直接连上安卓设备。

**入口**：本应用 → 设置 → 授权方式 → 第 4 项「网页版 ADB（USB，免回环端口）」。点进去是说明页，再点底部按钮用浏览器打开；它不会改变当前授权方式。

**归属与版本**（避免误认）：

- 网页由 **晨钟酱（CzJam）** 所有并维护，版本 **6.3.9**；
- 属于开源项目 **《搞机工具箱》Web 版**，许可证 **GPL-3.0**；
- 在线地址：<https://czjam.github.io/gjgjxweb/>
- 开源仓库：<https://github.com/CzJam/gjgjxweb>
- 本应用只提供入口和说明，**没有内置、也没有修改其网页代码**；网页内容与数据安全由该网页负责。
- 注意：「6.3.9」是网页工具的版本号，与 Smart Unlock 6.3.9 只是数字相同，两者没有隶属关系。

**适用设备**：

- 主机（打开网页的那一端）：**除 iOS 以外的设备都可以**——Windows、macOS、Linux、Android 平板或另一台手机；
- 浏览器：Chrome、Edge、Brave、Opera 等 Chromium 内核且支持 WebUSB 的浏览器；
- **iOS 不行**（iOS 浏览器没有 WebUSB），**Firefox 也不行**；
- 被调试端必须是**安卓设备**，并打开「USB 调试」。

**步骤**：

1. 目标安卓：开发者选项 → 打开「USB 调试」；
2. 连接数据线：电脑直连；手机作主机时用 OTG 转接头；两台手机用 C-to-C 数据线；
3. 在主机 Chrome / Edge 打开 <https://czjam.github.io/gjgjxweb/>（首次加载需要联网）；
4. 点网页里的「连接」→ 选择 USB 设备 → 在目标手机上允许 USB 调试授权；
5. 在网页的 ADB 终端执行命令（查看设备信息、临时授权、部署脚本等）。

**注意**：

- 网页是外部页面，首次打开必须联网；本应用本身仍不联网、不上传数据，打开后由浏览器直接与设备通信；
- 目标端必须开 USB 调试并确认 RSA 授权，不是「插上线就能用」；
- 手机作主机时，USB 口需要支持 OTG，供电不足会反复掉线；
- 应用会优先拉起 Chrome / Edge；没检测到时交给系统选择器，请手动选 Chromium 浏览器。

## 4. 首次配置

### 4.1 授予权限

首次打开会请求通知、附近设备权限；全部允许。Android 13+ 的通知权限也要允许，否则无线调试配对和前台服务通知会异常。

### 4.2 勾选蓝牙设备

1. 先让手表 / 耳机 / 手环与手机完成系统蓝牙配对；
2. 主页「蓝牙设备」卡片点「重新扫描」；
3. 勾选你要识别的设备。**新发现的设备默认不启用**，不勾选就不参与判定；
4. 需要「任一在线」就保持默认；需要所有勾选设备都在线，打开「多设备模式」；
5. 如果设备信号弱、隔墙容易误触发，可设置 RSSI 下限。

### 4.3 添加 WiFi（可选）

- Wi-Fi 解锁：连着指定 WiFi 就能单独触发解锁；
- WiFi 为必要条件：必须在蓝牙在线的同时连着指定 WiFi；
- 只能添加**当前已连接**的 WiFi：先连上它，再点「添加当前 WiFi」，不支持手输 SSID；
- 开启「增强防护 → WiFi → 绑定 BSSID + 要求非开放网络」后，开放网络默认不允许；确实需要时在同页打开「允许开放网络也成立」。

### 4.4 输入锁屏 PIN

在主页输入与系统锁屏一致的 4～16 位数字 PIN。PIN 会保存在应用设置里，并在部署时写入 shell 私有目录（权限 600），不会放到 `/sdcard`。

### 4.5 部署并启用

回到主页，点 **「部署并启用」**。看到状态变为「运行中」即可。

然后锁屏、熄屏，再点亮屏幕测试：如果蓝牙设备在线，应该自动输入 PIN 并进入桌面。

## 5. 日常使用

### 5.1 改设置

6.3 起，改开关、设备、WiFi 或 PIN 会**自动写入配置并热重载**，一般不需要重新部署。

只有以下情况需要再点「部署并启用」：

- 第一次使用；
- 切换授权方式（Shizuku / Root / 无线调试）；
- 升级或重装 APK；
- 守护被停用（连续两个冷却周期失败后）；
- 提示「设置已保存，但未写入守护」。

### 5.2 暂停 / 恢复

主页可「暂停 15 分钟 / 1 小时 / 4 小时」或输入自定义秒数；点「恢复」取消暂停。暂停期间守护仍在运行，只是不执行解锁。

### 5.3 看日志

设置 → 日志：

- 可自动刷新、复制、清空；
- 日志超过 1 MB 自动轮转为 `wu.log.old`；
- 反馈问题时附上日志截图，并注明手机型号与系统版本。

日志里常见的 `skip` 原因：

| 日志 | 含义 |
| --- | --- |
| `skip: already unlocked` | 亮屏时本来就没锁屏 |
| `skip: not on keyguard` | 当前不在锁屏界面 |
| `skip: 解锁条件不满足` | 蓝牙 / WiFi 条件没满足 |
| `skip: sim locked` | SIM 卡处于 PIN 锁定，防呆拒绝注入 |
| `skip: another attempt running` | 另一个解锁进程正在执行 |
| `skip: recent injection` | 1.5 秒内已经注入过 |
| 冷却 / 暂停 | `wu.state` 里有冷却截止或暂停时间 |

### 5.4 一键清理

主页「一键清理残留」会：

- 停守护、杀残留进程；
- 停监控服务、无线调试配对服务与 mDNS 发现；
- 删除 `/data/local/tmp/wu.*` 与旧 `/sdcard/watch-unlock`；
- **保留**应用内的设置、设备勾选与 WiFi 列表。

清理后解锁停止，需要重新「部署并启用」。

## 6. 可选功能

### 6.1 特殊锁屏返回 / 解锁后打开应用

有些 ROM 在音乐锁屏输入 PIN 后会停在音乐页：

- 打开「特殊锁屏返回及解锁打开指定应用」；
- 点「选择应用」选一个应用（单选），解锁后自动打开；
- 或打开「向右滑动」，解锁后执行一次右滑；
- 两者同时开启时优先打开应用；包名解析失败时退回右滑（若开启）。

如果打开应用无效，给本应用授予「后台弹出界面 / 自启动」权限。

### 6.2 增强防护

主页右侧「增强防护」卡片是总开关，二级页面有：

| 开关 | 建议 |
| --- | --- |
| 蓝牙身份匹配（只认 MAC） | **本版停用，不可操作**；随机 MAC 会导致正常设备被判离线 |
| MAC 对不上时允许同名设备 | 随上一项停用 |
| WiFi 绑定 BSSID + 要求非开放网络 | 需要防同名假热点时开启；2.4G/5G 需分别添加 |
| 允许开放网络也成立 | 默认关闭，按需开启 |
| 每次解锁前都现场查询设备状态 | 状态不准时再开；每次亮屏多花 0.2～0.35 秒，耗电略增 |

### 6.3 延长解锁（实验性，谨慎开启）

作用：设备在身边时临时清除锁屏密码，亮屏直接进桌面。

开启步骤：

1. 主页填写与系统一致的 PIN；
2. 高级 → 延长解锁；
3. 依次通过三级确认（5 秒 / 2 秒 / 2 秒），并校验系统 PIN。

恢复规则：

- 所有启用的蓝牙设备与 WiFi 条件都不再成立后，会立即、+0.5 秒、+1.5 秒各判定一次；
- **三次都离线**才写回原 PIN；
- 关闭开关、停止守护、一键清理会立即写回。

必须知道的风险：

- 密码清除期间，指纹 / 人脸会失效，恢复后要重新录入；
- 部分 ROM 不支持，可能直接失败（失败会回滚）；
- 守护被系统杀死、授权失效、重启后守护未运行等情况下，密码可能不会自动恢复；
- 不建议在主力机上长期开启。

异常处理：点「立即恢复锁屏密码」；仍不行就到系统设置里重新设置锁屏。

### 6.4 内置 ADB 控制台

无线调试页可直接执行一条 `adb shell` 命令，适合排查问题，例如：

```sh
sh /data/local/tmp/watch-unlock/wu-daemon.sh --check
```

会打印设备命中数、在线状态、WiFi、RSSI、锁屏、暂停、冷却、延长解锁等。

### 6.5 网页版 ADB

见 [3.4](#34-网页版-adbusb免回环端口637-新增备用通道)。它是外部网页，不是本项目自带的功能；入口只负责把浏览器打开到晨钟酱的页面。

## 7. 常见问题

| 问题 | 处理 |
| --- | --- |
| 亮屏完全没反应 | 看日志是否有 `skip`；确认守护状态「运行中」；确认至少勾选了一个设备 |
| 提示设备不在线 | `--check` 看 `watch_hit` / `match_mac`；确认设备已配对、名称未被系统改过 |
| 解锁很慢 | 关闭「每次解锁前都现场查询」和 RSSI 下限；看日志 `timing:` 分段 |
| 解锁后停在音乐页 | 开启「特殊锁屏返回」并选择应用，或开启右滑 |
| 改设置没生效 | 看设置页提示；若提示未写入守护，点「部署并启用」 |
| 重启后失效 | 守护随重启消失；重新启动 Shizuku 并授权，或重新配对无线调试，然后部署 |
| 小米 / 澎湃后台被杀 | 电池策略「无限制」、允许自启动；通知样式「原生样式」 |
| 无线调试配对失败 | 保持配对弹窗打开；下拉通知点「输入配对码」，或分屏后在「手动配对」里填配对端口 + 6 位码；关一次无线调试再打开；点「重新搜索配对服务」 |
| Root 点了允许仍不可用 | 6.3.7 首次等待 15 秒；再点「检测 Root 授权」，确认开发者选项 Root access 为「Apps and ADB」，root 管理器对「应用」放行 |
| Root 解锁偶发无响应 | 抓日志里的 `su` / `timing` 行反馈；先切到 Shizuku 观察是否复现 |
| 网页版 ADB 打不开设备 | 换 Chrome / Edge；确认数据线支持数据传输；目标端开 USB 调试并允许 RSA；手机主机需 OTG；iOS / Firefox 不行 |
| 连续两个冷却周期失败后停用 | 多半是系统 PIN 变了；在应用里改成新 PIN，再重新部署 |
| 延长解锁后指纹失效 | 预期行为；恢复密码后重新录入指纹 / 人脸 |
| 延长解锁没有自动恢复 | 点「立即恢复锁屏密码」；不行就系统设置里重设锁屏 |

## 8. 升级与卸载

### 升级

1. 用**同一签名**的新 APK 覆盖安装；
2. 打开应用，点一次「部署并启用」（守护脚本随 APK 更新，旧脚本不会自动替换）；
3. 检查设置是否保留，锁屏测试一次。

### 卸载 / 彻底清理

1. 先在应用里点「一键清理残留」；
2. 再卸载应用；
3. 如果之前开过延长解锁，清理前务必确认已「立即恢复锁屏密码」。

## 9. 安全提示

- PIN 会以明文保存在 shell 私有目录（权限 600），这是锁屏注入的必要代价；
- Shizuku / Root / 无线调试都会给应用 shell 能力，请只安装可信来源的 APK；
- 延长解锁会临时移除锁屏密码，设备丢失时风险很高；
- 应用不联网、不上传数据；无线调试的 mDNS 只在局域网内发现本机端口；
- 「网页版 ADB」是外部网页，首次加载需要联网；打开后由浏览器直连 USB 设备，数据不经过本应用。请从官方地址进入，网页内容与数据处理由晨钟酱的项目负责；
- 日志包含设备名、MAC、SSID，公开反馈前请先打码。
