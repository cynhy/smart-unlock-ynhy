# 蓝牙设备解锁 3.3：三档授权，没有 Shizuku 也能用

> 适用：Android 8.0 ～ 16（无线调试需要 Android 11 及以上）
> 授权：Shizuku / Root / 内置无线调试，任选其一

## 先说结论

3.3 是 1.1 的完整超集：1.1 能做的它全都能做，还多了三档授权、音乐锁屏返回、震动反馈、公告栏和 ADB 命令行。

新加的功能里，有一部分成熟度还不算高，但核心解锁链路和 1.1 一模一样。**推荐直接用 3.3.3**：它是 3.3 的修复版，修掉了「部署后沿用旧缓存、设备断开却仍解锁」的问题，并且和 3.3 同签名、可直接覆盖安装。只想图稳、不需要新功能的，继续留在 1.1 也完全没问题。

## 1.1 的功能，一个没少

亮屏自动解锁、任意蓝牙设备、逐设备勾选、任一/全部在线、Wi-Fi 独立解锁与必要条件、SIM 卡 PIN 防呆、临时暂停、日志页、一键清理、中英双语——全在。

## 3.3 新加了什么

**三档授权**

Shizuku 最稳，大多数人用这个；已经 root 的直接选 Root，不用装模块；既不想装 Shizuku 又不能 root 的，用内置无线调试——应用自己当 ADB 客户端，不需要电脑。

**音乐锁屏返回**

锁屏是音乐界面时，输完 PIN 常常退不出去。现在可以在设置里选：按包名打开指定应用主界面，或者直接向右滑动。两个都开时优先打开应用。

**震动反馈**

点按钮、拨开关时轻微震一下，嫌烦可以在设置里关掉。

**公告栏**

三级说明页，写了注意事项、开源组件鸣谢，点蓝字能看具体协议。

**ADB 命令行**

无线调试页顶部可以直接敲 `adb shell` 命令并执行。既然内置了 ADB，就别浪费。

## 一个必须养成的习惯

**改动任何选项后，回到主页重新点一次「部署并启用」。**

设置项一改就会重写配置并重启守护，但「部署并启用」还会顺手清掉上一轮的运行残留：旧守护进程、旧 logcat 监听、跨进程锁和在线判定缓存。不清的话，可能出现新旧状态混用——3.3.3 之前就出现过「设备其实已经断开，亮屏却还是解锁了」的情况，这个 bug 在 3.3.3 里已经修掉，部署和重启都会自动清缓存。

放心，部署只清运行残留，你的 PIN、设备勾选、Wi-Fi 和日志都不会丢。切换授权方式后也一样，记得重新部署一次。

## 哪些还不够成熟

说清楚，免得踩坑：

- **无线调试**：配对和连接是两个不同的端口，系统重启后端口会变，要重新配对。配对成功但连不上时，去开发者选项关一次再开「无线调试」。
- **音乐锁屏返回**：各家 ROM 的音乐锁屏实现差别很大，右滑手势可能被系统吃掉，这种情况优先用「打开指定应用包名」。
- **Root 档**：开发者选项里的 Root access 要设成「Apps and ADB」，否则会显示 Root 不可用。

其余功能和 1.1 一样稳。

## 安装注意

- 3.3 是正式密钥签名，3.0 是测试密钥签名，两个包**不能互装**。
- 从 1.1 / 2.0 升到 3.3 必须先卸载旧版，签名不同没法覆盖。
- 卸载会清空设备勾选和设置，升级前把 PIN、设备名、Wi-Fi 名记下来。
- 装完把应用和所用授权端（Shizuku）一起加进电池白名单。

## 怎么选

- 就想稳定自动解锁：1.1
- 要无线调试 / Root / 音乐返回 / ADB 命令行：3.3.3，推荐（3.3 的修复版）
