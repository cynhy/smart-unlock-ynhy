## 1. 这是什么

一个 Android 小工具：**当指定的蓝牙设备（手表、耳机、手环等）在线时，手机每次亮屏就自动输入锁屏 PIN 并解除锁屏**。

解决的问题：戴着手表或耳机时，手机明明就在手边，却每次亮屏都要手动划一下、输密码。

核心特点：

- **不需要 root**（默认走 Shizuku）；也可以用 Root，或手机自己连自己的无线调试；
- **解锁动作不依赖应用进程**：部署后由 shell 守护脚本执行，应用被划掉、被系统杀掉都不影响解锁；
- **事件驱动**：监听系统 `logcat` 的亮屏与 WiFi 事件，不做定时轮询；
- **在线判定有缓存**：应用监听蓝牙连接/断开广播，把结论缓存给守护，正常亮屏不需要重新查蓝牙；
- **设置热重载**：改开关、设备或 WiFi 只重写配置，守护在下一个事件前重读，不再整进程重启。

> 本项目会向系统注入锁屏密码，延长解锁还会临时清除锁屏密码。请先读 [安全与隐私](#16-安全与隐私)。

## 2. 适用平台与硬性限制

| 项目 | 要求 |
| --- | --- |
| 最低系统 | **Android 8.0（API 26）** |
| 内置无线调试 | **Android 11 及以上**（系统「无线调试」起始版本） |
| 网页版 ADB 备用通道 | 主机：除 iOS 外的设备 + Chromium 内核浏览器（Chrome / Edge / Brave / Opera，支持 WebUSB）；被调试端：Android + USB 调试；首次加载需联网 |
| 目标 SDK | 34 |
| 锁屏方式 | **PIN 码（纯数字，4～16 位）**，不支持图案、混合密码或单独用指纹解锁 |
| 必要权限 | 通知；Android 12+ 的「附近设备」（蓝牙）；无线调试配对需要网络权限 |
| 建议权限 | 电池优化白名单、自启动 / 后台弹出界面（国产 ROM 尤其需要） |
| 实测环境 | Android 12 / 13 / 14 / 16（LineageOS 24.0、HyperOS 3、鸿蒙 4.2 等） |

### 2.1 为什么最低是 8.0

不是解锁原理的限制，而是当前实现用了 Android 8.0 才有的前台服务与通知模型：

- `NotificationChannel`（API 26）
- `new Notification.Builder(context, channelId)`（API 26）
- `startForegroundService()`（API 26）

低于 8.0 时这些类/方法不存在，建通知或起前台服务会直接崩溃。APK 已声明 `minSdk 26`，7.1 及以下连安装都会被系统拒绝。

解锁链路本身（`sh` + `logcat -b events` + `wm dismiss-keyguard` + `input text`）在更老的系统上原理可行，但需要改通知模型、运行时权限与前台服务写法——当前没有做，也没有实测。

### 2.2 必须接受的前提

1. 锁屏必须是 **PIN**，且手机 PIN 与延时解锁使用的 PIN 一致；
2. 手机重启后守护进程消失，需要应用前台服务在授权可用时重新拉起；
3. 部分 ROM 会在后台清理时杀掉 shell 守护，此时解锁会失效，需重新部署；
4. 蓝牙设备使用随机 MAC 时，「只认 MAC」无法可靠工作，本版已将该严格模式停用（见 5.8）。

## 3. 工作原理

### 3.1 一句话流程

```
蓝牙设备在线 / 连上可信 Wi-Fi
        │
        ▼
屏幕点亮（系统 logcat events 事件）
        │
        ▼
wu-daemon.sh（shell uid 2000 常驻，事件驱动）
        │  读 /data/local/tmp/watch-unlock/config.conf 与 pin
        │  判断：目标设备在线？Wi-Fi 条件？暂停/冷却？已锁屏？
        ▼
wm dismiss-keyguard → input text <PIN> →（可选）特殊锁屏返回 / 打开指定应用
```

### 3.2 进程模型

| 进程 | 身份 | 作用 | 生命周期 |
| --- | --- | --- | --- |
| `com.watchunlock.app` | 普通应用 uid | 界面、配置下发、状态展示、蓝牙广播监听 | 随应用/系统，可被杀 |
| `wu-daemon.sh` | shell（uid 2000）或 root | 监听亮屏事件、执行解锁 | 部署后常驻，**不依赖应用存活** |
| `logcat -b events` | shell 子进程 | 向守护提供亮屏 / WiFi 事件流 | 随守护；退出后循环内自动重启 |
| `AdbPairingService` | 应用前台服务 | 无线调试配对、mDNS 发现、自动连接 | 配对期间 |

守护用 `setsid sh wu-daemon.sh &` 启动（没有 setsid 时退回 `nohup`），父 shell 退出后挂到 `init` 下：

- 划掉最近任务、系统强停应用 → **解锁照常**；
- Shizuku 被杀 / 关闭 → 守护仍在（默认 `RUN_MODE=detached`）；切成 `RUN_MODE=shizuku` 托管模式则随 Shizuku 结束；
- **手机重启 → 守护消失**，需授权引擎重新拉起（应用前台服务有 60 秒看门狗）。

### 3.3 一次解锁的时序

1. 守护收到 `power_screen_state [1,...]`（亮屏）或 `wifi_network_state_changed`；
2. 息屏事件只用于清零防抖，不触发；
3. 读 `wu.state`，检查 `disabled`、暂停、失败冷却；
4. 检查延长解锁状态（若已临时清除密码，先确认在线；离线则先做三次确认）；
5. 抢跨进程锁 `wu.unlock.d`；1.5 秒内已注入过则跳过；
6. 检查是否在锁屏；「未锁屏时跳过注入」默认开启；
7. 检查 SIM 卡 PIN 防呆（可选）；
8. 检查在线条件（蓝牙 / WiFi）与 RSSI 下限；
9. `wm dismiss-keyguard` 拉起 PIN 界面，`input text <PIN>` 注入；
10. 快路径未解锁时按 ROM 自适应走慢路径（再次 dismiss / 上滑、确认键盘、重试输入）；
11. 成功后（可选）打开指定应用或向右滑动；
12. 连续失败 3 次进入 600 秒冷却；连续两个冷却周期仍失败则停用守护，等待重新部署。

### 3.4 在线判定与缓存

| 环节 | 做法 |
| --- | --- |
| 启动 | 守护启动时刷新一次 `wu.present`，随后不做任何轮询 |
| 应用监听 | 应用注册蓝牙连接/断开广播，收到事件后调用 `wu-daemon.sh --present track` |
| 正常亮屏 | `online=yes && track=1 && 应用进程存活` 时直接信任缓存，0 次进程查询 |
| 应用不在 | 应用被杀、未启动或没有蓝牙权限时，守护现场查询一次；应用还应调用 `--untrack` 撤销登记 |
| 查询失败 | `dumpsys bluetooth_manager` 空输出、极短输出或没有蓝牙内容时记为 **unknown**，不当作离线 |
| 可选现查 | 增强防护里可打开「每次解锁前都现场查询设备状态」，每次亮屏都现查（慢 200～350ms） |

`wu.present` **不随部署/重启删除**：它记录「应用是否在监听蓝牙事件」。删掉它会让守护永久退化成每次亮屏现查，这也是 3.9 修复的问题。

## 4. 三档授权

三种方式执行的是**同一套守护脚本**，区别只在「谁给 shell 身份」。设置页可随时切换，但**切换后必须重新点「部署并启用」**。

| 方式 | 需要什么 | 稳定性 | 适合谁 | 主要限制 |
| --- | --- | --- | --- | --- |
| **Shizuku**（默认） | 安装并运行 Shizuku，在本应用点「请求授权」 | 最稳 | 大多数用户 | Shizuku 被系统回收后需重新启动；建议加入电池白名单 |
| **Root** | 设备已 root，`su` 弹窗放行 | 稳定（6.3.7 起明显改善） | 已 root 的用户 | 开发者选项 Root access 需为「Apps and ADB」；部分 ROM 的 su 只对 adb 开放 |
| **内置无线调试** | 开发者选项打开「无线调试」，用配对码配对一次 | 中等 | 不想装 Shizuku 也不能 root | 需 Android 11+；重启后无线调试自动关闭、端口变化，需重新配对 |

### 4.1 Shizuku

1. 安装并启动 Shizuku（可用无线调试或 root 启动）；
2. 本应用 → 设置 → 授权方式 → Shizuku → 「请求授权」；
3. 回到主页 → 「部署并启用」。

### 4.2 Root

1. 开发者选项 → Root access 设为「Apps and ADB」（不同 ROM 名称略有差异）；
2. 本应用 → 设置 → 授权方式 → Root；
3. 点「检测 Root 授权（会弹出 su 请求）」并在弹窗里选「允许」；首次给 15–30 秒的确认时间；
4. 回到主页 → 「部署并启用」。

无需 Magisk 模块。若提示 Root 不可用，说明 `su` 没有对本应用放行，或设备实际未 root。

**6.3.7 起的 Root 稳定性修复**：

- RootBridge 复用一条常驻 `su` 交互 shell，不再每次操作都重新拉起 `su`（亮屏解锁、刷新状态更快，超时更少）；
- 每条命令写入唯一脚本文件，修掉了并发调用共用 `wu-root.sh` 导致的互相覆盖；
- 首次检测给 15 秒（部署时 20–30 秒），避免「刚点允许，应用却已把失败缓存 2 分钟」；
- 失败缓存从 120 秒缩短到 20 秒，授权成功后缓存 5 分钟；
- 守护改用 `setsid` 脱离 `su` 会话，`su` 退出时不会连带收走守护；
- 状态检测移出 UI 线程，Root 首次弹窗不会再让主界面卡住。

### 4.3 内置无线调试（随包官方 ADB，不依赖 Shizuku）

应用内置**官方 AOSP adb 客户端**（Termux android-tools 37.0.0p1 构建，Apache-2.0），以应用自身的 uid 执行 `adb pair` / `adb connect` / `adb shell` / `adb push`，手机自己连本机的无线调试端口。**6.3.7 起已完全移除第三方 Kadb 内核**，6.4.3 沿用同一实现；APK 不再包含 Kotlin、Bouncy Castle、Okio 等依赖。

实现要点：

- 可执行文件 `libadb.so` 打包在 `lib/arm64-v8a/`，安装后由系统解压到 `nativeLibraryDir`（Android 10+ 只允许在这里执行二进制）；
- 依赖库打包在 `assets/adb-libs.zip`，首次使用时解压到 `filesDir/adb/lib` 并设为只读（Android 14 要求动态加载的库不可写）；
- 运行时注入 `HOME`（存放 `adbkey`，配对密钥只生成一次）、`LD_LIBRARY_PATH`，并给每条命令加 `-P 5039`，避开其它 adb 服务；
- `adb` 客户端会自行拉起 adb server；连接验证用 `adb -s <host:port> shell echo wu-ok`；
- Termux 构建的 `adb mdns` 不可用，端口发现仍由应用内的 `AdbMdns`（NsdManager）完成。
- APK 体积因此变化：`libadb.so` 约 3.4MB（stored，不压缩），`assets/adb-libs.zip` 约 4.5MB；首次配对时会解压依赖，需要几秒，之后不再重复解压。

当前流程：

1. 允许本应用发送通知（用通知方式输入配对码时需要）；
2. 本应用「无线调试」页点「开发者选项」，系统跳到开发者选项，并尽量把「无线调试」滚动到可见位置；
3. 点「无线调试」左侧进入子页面，打开开关；
4. 点「使用配对码配对设备」，**保持弹窗打开**；
5. 应用通过 mDNS 自动发现本机的配对端口，同时并行发现连接端口；输入配对码三选一：
   - **通知内联输入**：下拉展开通知，点「输入配对码」，在通知里输入 6 位配对码；不要点通知正文；
   - **大按钮输入**：点通知里的「大按钮输入」，打开独立输入页，填 6 位码后点一次大号「发送」；
   - **分屏手动配对**：本应用与设置页分屏显示，在「手动配对」里填配对端口和 6 位码，点「配对」；
   **无论哪种方式，都不要关闭系统「使用配对码配对设备」弹窗**——离开弹窗后配对端口与配对码会立即失效；
6. 配对成功后自动连接本机 ADB；连接端口也可用页面下方的「连接测试」手动重连。

> **分屏 / 小窗提示**：系统设备码卡片在离开「使用配对码配对设备」页面后可能收起，配对码会立即失效。推荐把本应用与设置页分屏，或用小窗打开本应用；「大按钮输入」页也会显示同样的提示。

**无线调试修复（6.4.0 / 6.4.3）**：

- **6.4.0**：mDNS 发现重写——解析队列、同一服务解析失败重试 2 次、发现启动失败重试 5 次（间隔 1.5 秒），修掉长时间搜不到配对服务；
- **6.4.0**：连接端口从配对服务启动时就并行发现并缓存；配对成功后先试缓存 / 上次端口，25 秒内持续等待新端口，不再立即报「没找到连接端口」；
- **6.4.0**：配对阶段每 8 秒重启一次配对发现（最多 6 次），连接阶段每 4 秒重启一次连接发现（最多 8 次）；
- **6.4.0**：相同状态与文案不重复刷新通知，避免通知内联输入框被收起、点「发送」没反应；
- **6.4.0**：通知新增「大按钮输入」动作，打开独立输入页；「发送」按钮高度 56dp、文字 20sp，点一次即提交；
- **6.4.3**：输入页补充分屏 / 小窗提示，说明离开系统设备码页面后卡片可能收起、配对码失效。

注意：

- MIUI / 澎湃如果通知里没有输入框，到 系统设置 → 通知管理 → 通知显示设置，把通知样式切换为「原生样式」；
- 建议把本应用电池策略设为「无限制」，避免配对服务被后台清理；
- 重启手机后无线调试会自动关闭，需重新打开并再配对一次。

### 4.4 网页版 ADB（USB，免回环端口，6.3.7 起提供）

**为什么加这个入口**：谷歌可能进一步收紧「本机回环 ADB」（`127.0.0.1`）的配对与授权。无线调试一旦失效，可以用网页版 ADB 走另一条路：不经过手机自己的 adbd 回环端口，而是用 **WebUSB** 把目标安卓设备直接连到另一台设备，在浏览器里执行 ADB 命令。

**归属与版本**（应用内会原样展示，别写成我们自己的）：

- 网页由 **晨钟酱（CzJam）** 所有并维护，版本 **6.3.9**；
- 属于开源项目 **《搞机工具箱》Web 版**，许可证 **GPL-3.0**；
- 在线地址：<https://czjam.github.io/gjgjxweb/>
- 开源仓库：<https://github.com/CzJam/gjgjxweb>
- 本应用只提供入口和使用说明，**没有内置、也没有修改其网页代码**；网页的版权、内容和数据安全由该网页自行负责。

> 注意：这里的 **6.3.9** 是网页工具的版本号，与 Smart Unlock 的版本号（6.4.3）没有关系，两者也没有隶属关系。

**能用在哪些设备上**：

- 主机（跑浏览器的那一端）：**除 iOS 以外的设备都可以**——Windows、macOS、Linux、Android 平板或另一台手机；
- 浏览器必须是 Chromium 内核且支持 WebUSB：Chrome、Edge、Brave、Opera 等；
- **iOS 不行**（iOS 浏览器没有 WebUSB），**Firefox 也不行**；
- 被调试端必须是**安卓设备**，并且打开「USB 调试」。

**步骤**：

1. 目标安卓：开发者选项 → 打开「USB 调试」；
2. 连接数据线：电脑直连；手机作主机时用 OTG 转接头；两台手机用 C-to-C 数据线；
3. 在主机 Chrome / Edge 打开 <https://czjam.github.io/gjgjxweb/>（首次加载需要联网）；
4. 点网页里的「连接」→ 选择 USB 设备 → 在目标手机上允许 USB 调试授权；
5. 在网页的 ADB 终端里执行命令（查看设备信息、临时授权、部署脚本等）。

**入口位置**：本应用 → 设置 → 授权方式 → 第 4 项「网页版 ADB（USB，免回环端口）」。它只是备用入口，不会改变当前授权方式；点进去先看到说明页，再点页面底部「打开网页版搞机工具箱 6.3.9」由浏览器打开。应用会优先拉起 Chrome / Edge，没装时交给系统选择器；也可以点「复制网页地址」手动打开。

**注意**：

- 网页是外部页面，首次打开必须联网；本应用本身仍不联网、不上传数据，打开后由浏览器直接与设备通信；
- 不要把它当成「不用打开 USB 调试」的魔法：目标端必须开 USB 调试，并确认 RSA 授权；
- 若手机主机的 USB 口不支持 OTG / 供电不足，会出现连不上或反复掉线，换 OTG 转接头或改用电脑。

### 4.5 什么时候还需要授权引擎

| 场景 | 是否需要授权引擎 |
| --- | --- |
| 日常亮屏解锁（守护已在跑） | **不需要** |
| 首次部署 / 重新部署 | 需要 |
| 改设置（热重载） | 需要（应用要通过授权写入配置） |
| 暂停 / 恢复 / 一键清理 / 读状态 | 需要 |
| 蓝牙断开后刷新在线缓存 | 需要 |
| 守护被杀后 60 秒看门狗拉起 | 需要 |
| **手机重启后恢复守护** | **需要**（Shizuku 未开机自启时必须重新授权） |

## 5. 功能详解

### 5.1 蓝牙目标设备

- 主页「蓝牙设备」卡片读取系统里**已配对**的设备（需要「附近的设备」权限），点「重新扫描」可刷新；
- 新发现设备默认**不启用**，避免首次安装时把所有耳机/手表都算进「任一在线」；
- 只有勾选启用的设备参与判定；
- 两种模式：
  - **任一在线**（默认）：任意一个启用设备在线即满足；
  - **全部在线**（「多设备模式」）：所有启用设备都必须在线；
- RSSI 下限（`RSSI_MIN`）：信号太弱视为不在线，避免隔墙误触发。

### 5.2 Wi-Fi 条件

两个独立开关，可组合：

| 开关 | 含义 |
| --- | --- |
| Wi-Fi 解锁 | 连上列表中任一启用的 SSID 即可触发解锁（蓝牙不要求） |
| Wi-Fi 为必要条件 | 蓝牙在线之外，还必须连着可信 WiFi 才解锁 |

限制：**只能添加「当前已连接」的 Wi-Fi**，不支持手动输入 SSID（应用读不到未连接网络的凭据信息）。需要添加某个网络时，先连上它，再点「添加当前 WiFi」。

开启「增强防护 → WiFi → 绑定 BSSID + 要求非开放网络」后：

- 添加时记录 BSSID 与安全类型；
- 运行时同时比对 SSID 与 BSSID（连接状态用 `cmd wifi status` 判定）；
- 开放（无密码）网络默认被拒绝；确实需要时打开同页「允许开放网络也成立」；
- 同一路由器的 2.4G / 5G 频段会被视为不同网络，需要分别添加。

### 5.3 锁屏 PIN

- 4～16 位纯数字；
- 保存在应用私有 `SharedPreferences`，部署时写入 `/data/local/tmp/watch-unlock/pin`（权限 600）；
- 延长解锁另有一份副本 `extpin`（同样 600），用于自动写回；
- `config.conf` 中**不出现 PIN 明文**；
- 注入方式以 `input text` 为主，慢路径会用 `input keyevent` 清空后重试；
- **不要**用图案或混合密码，脚本无法可靠注入。

### 5.4 SIM 卡 PIN 防呆

- 默认关闭；
- 开启后，解锁前检查 `gsm.sim.state`：若 SIM 处于 PIN / PUK 锁定状态，**拒绝注入手机 PIN**，避免把手机锁屏密码打到 SIM 上导致锁卡；
- 代价是多一次状态检查，解锁速度与成功率会略降。

### 5.5 暂停与恢复

主页提供「暂停 15 分钟 / 1 小时 / 4 小时」与自定义秒数，以及「恢复」。

- 暂停写入 `wu.state`，守护进程不退出，只是跳过解锁；
- 适合临时把手机交给别人，或不需要自动解锁的时段。

### 5.6 震动反馈

- 设置页有总开关，默认开启；
- 点击按钮、切换开关时轻微震动（`VIRTUAL_KEY`）；
- 关闭后应用内交互不再震动，不影响解锁本身。

### 5.7 特殊锁屏返回及解锁打开指定应用

锁屏是音乐界面时，输完 PIN 常常退不出去。提供两种方式，可单独或同时开启：

| 方式 | 行为 | 备注 |
| --- | --- | --- |
| 打开指定应用 | 解锁后按 `MAIN + LAUNCHER` 解析真实组件并 `am start` | 同时开启时优先这一种；解析失败可用 monkey 兜底 |
| 向右滑动 | 解锁后执行一次右滑手势 | 部分 ROM 的音乐锁屏会截获手势，此时改用打开应用 |

- 「选择应用」读取全部已安装应用，默认只列桌面可启动应用，分第三方/系统两页并支持搜索；
- 已添加的应用为**单选**，同一时间只打开一个；
- 打开指定应用无效时，给本应用授予「后台弹出界面 / 自启动」权限。

### 5.8 增强防护

主页右侧卡片是总开关，二级页面包含：

| 功能 | 状态 | 说明 |
| --- | --- | --- |
| `蓝牙身份匹配（只认 MAC）` | **暂时停用（界面保留，不可操作）** | 蓝牙设备普遍使用随机 MAC，开启后会把正常设备判成不在线，导致完全无法解锁。内核已关闭，判定恢复为「先看 MAC，对不上再看名称」 |
| `MAC 对不上时允许同名设备` | 随上一项停用 | 修好后重新开放 |
| `WiFi 绑定 BSSID + 要求非开放网络` | 可用 | 见 5.2 |
| `允许开放网络也成立` | 可用，默认关闭 | 仅在上面的绑定开关打开时有意义 |
| `每次解锁前都现场查询设备状态` | 可用，默认关闭 | 更稳，但每次亮屏多花约 0.2～0.35 秒，耗电略微增加 |

### 5.9 延长解锁（实验性，默认关闭）

原理：确认设备在线并**成功解锁一次**后，用 `locksettings clear` 清除锁屏密码，并 `set-disabled true`，之后亮屏不再注入 PIN。

开启流程：

1. 在主页填写与系统一致的锁屏 PIN；
2. 「高级 → 延长解锁」；
3. 连续通过三级确认（5 秒 / 2 秒 / 2 秒强制等待），并校验系统 PIN。

恢复策略：

- 所有启用的蓝牙设备与 WiFi 条件都不再成立后，**立即、+0.5 秒、+1.5 秒各判定一次**，三次都离线才 `set-pin` 写回原 PIN；
- 任何一次判定为「在线」或「无法判定」都放弃本次恢复，避免一次空 dump 把密码写回；
- clear / restore 共用互斥锁 `wu.extend.d`；清除前还会再复核一次在线；
- 关闭开关、停止守护、一键清理会立即写回；
- 守护启动时若发现有残留的延长状态，会按上述规则恢复。

风险：

- 密码清除期间，系统录入的指纹 / 人脸会失效，恢复后需要重新录入；
- 部分 ROM 可能不支持或直接失败（失败会自动回滚）；
- 守护被系统杀死、授权失效、重启后守护未运行等异常情况下，密码可能不会自动恢复；
- 出现异常时点「立即恢复锁屏密码」，或在系统设置里重新设置锁屏。

### 5.10 公告栏、日志、清理、ADB 控制台、语言

| 功能 | 说明 |
| --- | --- |
| 公告栏 | 版本与签名说明、重要提醒、按功能的使用说明、更新日志、开源致谢 |
| 日志页 | 查看 `wu.log`，支持自动刷新、复制、清空；超过 1 MB 自动轮转为 `wu.log.old` |
| 一键清理 | 停守护、杀残留、停监控与配对服务、删除 `/data/local/tmp/wu.*` 与旧 `/sdcard/watch-unlock`；保留设置与设备勾选 |
| 内置 ADB 控制台 | 无线调试页可直接执行一条 `adb shell` 命令，回显退出码与输出 |
| 网页版 ADB | 设置 → 授权方式第 4 项（仅入口，不改授权方式），点击进入说明页，再打开晨钟酱的《搞机工具箱》Web 版 6.3.9；WebUSB 直连安卓，不依赖回环端口（详见 4.4） |
| 语言 | 默认跟随系统，可强制中文 / English |

## 7. 设置如何生效

6.3 起，改设置不再重启守护：

| 动作 | 改设置（热重载） | 点「部署并启用」 |
| --- | --- | --- |
| 重写 `config.conf` / `pin` / `extpin` | 是 | 是 |
| 守护重读配置 | 是（下一个事件前） | 是（重启后读取） |
| 杀旧守护 + 旧 logcat 监听 | 否 | 是 |
| 清 `wu.daemon.d` / `wu.unlock.d` 锁 | 否 | 是 |
| 清 `wu.state`（失败计数 / 冷却 / disabled） | 否 | 是 |
| 清 `wu.cm*` / `wu.kw*` / `wu.bt*` / `wu.hit*` / `wu.ui*` 临时文件 | 否（按进程号独立，残留无害；部署会清） | 是 |
| 保留 `wu.present` 在线缓存 | 是 | 是 |
| 重写守护脚本 `wu-daemon.sh` / `wu-stop.sh` | 否 | 是 |
| 保留设置、设备勾选、日志 | 是 | 是 |

因此：

- **日常改开关、设备、WiFi、PIN**：自动写入配置，无需重启，也无需重新部署；
- **首次部署、切换授权方式、升级 / 重装、守护被停用（`disabled`）**：必须点「部署并启用」；
- 如果热重载时守护不在运行，应用会提示「设置已保存，但未写入守护」，此时需要部署。

## 10. 解锁决策逻辑

```
亮屏 / WiFi 事件
  ├─ 息屏事件：只清防抖，不触发
  ├─ disabled（连续两个冷却周期失败）：守护退出
  ├─ 暂停中 / 冷却中：跳过
  ├─ 抢 wu.unlock.d 失败：跳过（另一个进程正在解锁）
  ├─ 1.5 秒内已注入：跳过
  ├─ 延长解锁已激活：
  │    ├─ 仍在线：不注入
  │    └─ 不在线：三次确认（立即 / +0.5s / +1.5s）→ 全离线才恢复 PIN 并继续常规注入
  ├─ POCKET_GUARD=1 且未亮屏：跳过（本版无界面开关，默认不生效）
  ├─ 已解锁且 SKIP_WHEN_UNLOCKED=1：跳过
  ├─ SIM_GUARD=1 且 SIM 锁定：拒绝注入
  ├─ 在线条件不满足：跳过
  ├─ RSSI 低于下限：跳过
  ├─ dismiss + input text → 成功
  └─ 失败 → 慢路径重试 → 失败计数 +1 → 3 次进入 600 秒冷却
```

「在线」可能是蓝牙、WiFi 或二者组合，取决于 `WIFI_UNLOCK` / `WIFI_REQUIRED`：

| 配置 | 在线条件 |
| --- | --- |
| 默认 | 启用的蓝牙设备满足 `any` / `all` |
| `WIFI_UNLOCK=1` | 蓝牙条件成立 **或** 可信 WiFi 成立 |

本版没有做系统化的整机功耗测量；以下数据来自代码路径与日志分段（`DEBUG_TIMING=1`）：

## 14. 常见问题

| 现象 | 排查 |
| --- | --- |
| 亮屏不解锁 | 先看日志页是否有 `skip`：`already unlocked`、`not on keyguard`、`解锁条件不满足`、冷却中、暂停中 |

| 延长解锁后指纹失效 | 属预期：清除密码会让生物识别作废，恢复后重新录入 |
| 延长解锁没有自动恢复 | 点「立即恢复锁屏密码」；若仍失败，到系统设置重新设置锁屏 |
| Root 点了「允许」仍提示不可用 | 6.3.7 已把首次等待放宽到 15 秒、失败缓存缩短到 20 秒；仍失败时到设置页点「检测 Root 授权」重试，确认开发者选项 Root access 为「Apps and ADB」 |

## 15. 已知限制

1. **仅 PIN**：图案、混合密码、纯指纹方案都不支持。
2. **随机 MAC**：严格 MAC 匹配已停用；当前按「MAC 优先，对不上再看名称」，同名设备存在被冒用的可能。
3. **重启**：守护不会自动复活；Android 重启后首次解锁也必须手动完成。
4. **ROM 差异**：锁屏界面、键盘、音乐锁屏、后台清理策略各不相同，部分 ROM 需要额外权限或无法稳定工作。
5. **无线调试**：重启后关闭、端口变化；每次重启都要重新配对。系统不向第三方应用开放连接端口读取，端口依赖 mDNS 发现；部分 ROM 的 mDNS 不稳定，失败时请用分屏 + 手动配对填写端口。
6. **延长解锁**：实验性功能，生物识别会失效，异常情况下可能无法自动恢复密码，不建议在主力机上长期开启。
7. **SIM 防呆**：只根据 `gsm.sim.state` 判断，个别 ROM 的属性可能不准。
8. **多用户 / 工作资料**：脚本固定 `--user 0`，不支持其他用户。
9. **无联网能力**：应用不联网，因此没有自动更新与远程推送。
10. **网页版 ADB 是外部页面**：首次使用必须联网加载；不内置、不修改晨钟酱的网页；iOS 与 Firefox 不能作为主机；只能调试安卓设备。
11. **回环 ADB 政策风险**：若谷歌在系统层收紧 `127.0.0.1` 的 ADB 配对，内置无线调试可能整体失效；网页版 ADB 是备用通道，但仍需目标设备开 USB 调试并物理接线。

## 16. 安全与隐私

- **PIN 明文**：为了在锁屏时注入，PIN 必须以明文保存。位置是 `/data/local/tmp/watch-unlock/pin`（权限 600，仅 shell/root 可读），不会写入 `/sdcard`，也不会写进 `config.conf`。请自行评估风险。
- **提权面**：Shizuku / Root / 无线调试都会给应用执行 shell 的能力；请只安装可信来源的 APK，不要在不可信设备上开启延长解锁。
- **共享存储**：脚本与配置放在 `/data/local/tmp`，而不是 `/sdcard`，避免被任意应用改写后以 shell 身份执行。
- **配置注入防护**：应用写入蓝牙名、SSID 等自由文本时会过滤控制字符与 shell 元字符，并用单引号包裹。
- **不联网**：应用没有网络权限用途（无线调试配对除外，mDNS 只在局域网内发现端口），不上传任何数据。
- **外部网页**：「网页版 ADB」只是把浏览器打开到 `czjam.github.io/gjgjxweb/`，不打包其代码；打开后由浏览器直连 USB 设备，数据不经过本应用。网页本身的隐私与数据处理由晨钟酱的项目负责，请从官方地址进入。
- **延长解锁**：会临时移除锁屏密码。设备丢失、守护被杀或恢复失败时，手机可能处于无锁状态；这是该功能的核心风险。
- **日志**：日志包含设备名称、MAC、SSID 等本地信息，反馈前请自行检查是否要打码。

| 改设置 | 重启守护，建议重新部署 | **热重载**，不重启；首次/切换引擎/升级才需部署 |

| 在线查询失败 | 当作离线 | 记为 **unknown**，不触发延长解锁恢复 |
| 延长解锁恢复 | 断开即写回 PIN | **三次独立确认**（立即 / +0.5s / +1.5s）才写回 |
| 临时文件 | 全局共用 `wu.bt` / `wu.cm` | **按进程号独立**，消除并发半截 dump |
| MAC 严格匹配 | 可开启 | **暂时停用**（随机 MAC 导致无法解锁），界面保留但不可操作 |
| 解锁方式 | 文档提「上滑 / 关闭键盘」切换 | **没有该开关**；脚本自动在 dismiss 与上滑之间切换 |
| Root 执行 | 每次操作重新 `su -c`，共用 `wu-root.sh` | **常驻 su shell + 唯一脚本文件**；失败缓存 20 秒；setsid 守护 |
| 回环 ADB 失效 | 无备用方案 | 设置 → 授权方式第 4 项新增 **网页版 ADB**（WebUSB，外部 GPL 页面） |
| 无线调试内核 | Kadb（Kotlin） | **官方 AOSP adb 二进制**（Termux android-tools 构建，6.3.7 起），去掉 Kotlin 与 Bouncy Castle 依赖 |
